# テレビ向けプレビューの配信

`v<IPK バージョン>-alpha.<番号>-preview` タグを push すると、ワークフローが IPK をビルドし、署名付き画面更新を作成します。公開済み 0.1.3 IPK で更新の取得と起動を試し、署名、固定アセットの互換性、公開中の版との順序を確認した後に Pages へ配信します。公開されたデータがビルドした更新と一致してから GitHub Release を公開します。

署名鍵は `github-pages` 環境の Actions secret で管理します。鍵をソースやログに入れないでください。固定アセットや起動処理を変えると 0.1.3 IPK との互換性検査は失敗します。その場合は既存テレビへの影響と再導入手順を明示し、配信方式を確認してから互換性条件を変更してください。

失敗したジョブは Actions から再実行できます。Pages 配信の直前にも公開中の版を検査するため、古いタグの再実行は新しい更新を巻き戻せません。成果物の保持期限が切れた場合はビルドから再実行してください。

Release 作成中に失敗すると、GitHub CLI が作成したドラフトが残る場合があります。公開済みの画面更新はすでにテレビへ届くこともあります。再実行前に該当タグの Release／ドラフトと各添付ファイルの名前・SHA-256 を確認し、期待する成果物と一致するかを調べてください。既存の公開物や不一致のドラフトは自動で上書きせず、原因を解決してから管理してください。

CI とブラウザによる検証は、LG テレビと Galaxy 実機での接続・再生・更新の確認を代替しません。
